# CS-360-Final-Project

This application was designed to help individuals keep track of their weight loss day-to-day. I created this application so that individuals could set a goal weight, input daily weight measurements, and set alerts for when they finally reach their goals. 

The application features a simple interface that allows users to log in or create a new user account, then takes them to the daily journal. The main diary interface is designed to give users a simple at-a-glance idea of where they are on their goals. There's also the goals screen, which allows users to enter their weight in either kilograms or pounds, depending on their preference, and tracks it on their calendar. I think the most successful UI element I designed is the color-coding system that marks days when the goal is achieved with a green calendar card and days when you fell short with a red card. There's also the gold card, which indicates when they are likely to reach their goal under ideal conditions. 

Initially, I started by familiarizing myself with the Android Studio interface. I found myself throwing things at the wall to see what stuck. After I had become more familiar with what each element did and how I would use it, I started working out how each element would move from point A to point B. I created a wireframe to understand how each screen would flow. Once the layout was defined, I moved on to the programming phase. This phase of the cycle was a bit more experimental. While I had a solid understanding of Java, I didn't have a strong grasp of how SQLite worked, and I went through many iterations before I felt comfortable. Now that I'm more comfortable, I can see myself using the things I've learned to create a more stable version, as well as more closely follow CRUD operations in the SQLite database. 

While creating this application, I used a variety of different testing methods to ensure that the program was functioning correctly. For basic testing, I used the Log.d() statements to check my output. When it came to more hands-on items, I found myself testing across a variety of different platforms and configurations to see how the program functioned. And when all else failed, I would create the functions in a "sandbox" and test my output using the tried-and-true print statements. Testing is an important part of the process because it's easy to let things slip past you if you assume your code is bulletproof. Even under the best circumstance things will slip through so testing is helpful to minimize the amount of potential errors that make it to production. 
I found myself innovating in a few areas, whether that was creating an custom adapter to turn the card I created into page elements that dynamically responded to input or creating a Regex expression that made logging in more akin to what you might find in an application outside a classroom. Each of these challenges required me to think hard about a solution and adjust my program to fit my needs. 

I think the item I'm most proud of is the diary itself. I could have made things simple for myself and used a calendar widget but part of me wanted to throw myself a challenge. I started by creating a gridview to use as the staging area. From there, I created individual cards that would hold the information I needed. Once the two items were ready, I created a GridviewCreator class that populated the different cards with the properties and listeners to make them interactive and responsive. In the end I was very happy with what I created and can't wait to put my skills to good use.
